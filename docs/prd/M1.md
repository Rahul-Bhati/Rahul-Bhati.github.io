# PRD — M1: Foundation (Supabase + Prisma + env + docs)

## Goal
Stand up the data layer the rest of the platform builds on: a Supabase Postgres database modeled with Prisma, seeded from today's hardcoded content, plus project plumbing and milestone docs. De-staticify the build for Vercel.

## Why
Everything downstream (auth, dashboard, CMS, dynamic SEO pages) reads/writes a database. There is none today — content lives in `src/lib/content.ts`. M1 introduces persistence without changing the public UI yet.

## Scope
- **Docs:** `docs/PROGRESS.md` + `docs/prd/M1.md … M6.md`.
- **Deps:** `@prisma/client`, `prisma`, `@supabase/supabase-js`, `bcryptjs` (+types), `jose`, `zod`, `react-markdown`, `remark-gfm`, `rehype-sanitize`, `tsx`.
- **Env:** `.env.example` (committed) + `.env.local` (gitignored) with `DATABASE_URL`, `DIRECT_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SITE_URL`.
- **Schema** (`prisma/schema.prisma`):
  - `Post(id, slug*, title, excerpt, contentMarkdown, coverImageUrl?, readingTime?, status PostStatus, publishedAt?, metaTitle?, metaDescription?, keywords[], ogImageUrl?, createdAt, updatedAt)` + relations `media[]`, `crossPosts[]`.
  - `Project(id, slug*, title, description, status ProjectStatus, gradient, year, overview, problem, techStack[], demoUrl?, githubUrl?, coverImageUrl?, metaTitle?, metaDescription?, keywords[], ogImageUrl?, createdAt, updatedAt)` + `media[]`.
  - `Media(id, url, type MediaType, alt?, width?, height?, postId?, projectId?, createdAt)`.
  - `CrossPost(id, postId, platform, label, href, order)`.
  - `SiteLink(id, group LinkGroup, platform, label, href, tone?, order, visible, createdAt, updatedAt)` — backs socials, hero pills, footer, YouTube, etc.
  - `PageView(id, path, referrer?, country?, device?, sessionHash?, isBot, createdAt)`.
  - `Place(id, name, country, order)`.
  - Enums: `PostStatus{DRAFT,PUBLISHED}`, `ProjectStatus{ACTIVE,IN_PROGRESS,SHIPPED}`, `MediaType{IMAGE,VIDEO}`, `LinkGroup{SOCIAL,PILL,FOOTER}`.
- **Client:** `src/lib/db.ts` — HMR-safe Prisma singleton.
- **Seed:** `prisma/seed.ts` — port `projects`, `posts`, `socials`/`pills`/`socialLinks`, `places` from `src/lib/content.ts` into the DB (map status strings → enums, paragraph arrays → markdown, icon components → `platform` strings).
- **Config:** `next.config.ts` — confirm no `output: 'export'`; add `images.remotePatterns` for `*.supabase.co` → `/storage/v1/object/public/**`. `package.json` — add `db:migrate`, `db:seed`, `db:studio`, `prisma.seed` hook.

## Out of scope
Public UI still reads `content.ts` (swap happens M4/M5). No auth/admin yet.

## Acceptance tests
1. `npx prisma migrate dev --name init` creates tables with no error.
2. `npm run db:seed` inserts all current projects, posts, links, places.
3. `npx prisma studio` shows the seeded rows.
4. `npm run build` passes (no static-export error).

## Gate (exit)
Migration applied + seed populated + build green → unlocks **M2**.

## Human steps required
Create a Supabase project and paste the connection strings + keys into `.env.local` (I'll provide the exact template and where to copy each value from).
