# PRD — M3: Dashboard + analytics

## Goal
`/admin` shows real visit data and a live SEO/performance score.

## Why
Rahul wants to see how the site performs — visits, top pages, SEO health — from his own dashboard, owning the data.

## Scope
- **Capture:** `src/app/api/track/route.ts` (`POST`) writes a `PageView` row: path, referrer, device (UA parse: desktop/mobile/tablet), `country` (from `x-vercel-ip-country` header), `sessionHash` (daily-rotating SHA-256 of IP+UA+salt — no raw IP/PII), `isBot` (UA heuristic). Honors `DNT`. Rate-limited.
- **Beacon:** `src/components/analytics-beacon.tsx` — client component in root layout; fires `navigator.sendBeacon('/api/track', …)` on route change (App Router `usePathname`). Skips `/admin`.
- **Aggregation:** `src/lib/analytics.ts` — queries for total views, unique visitors (`distinct sessionHash`), views-per-day (last 30d), top paths, top referrers (bots excluded).
- **Dashboard** (`src/app/admin/page.tsx`, RSC): stat cards + a views-over-time bar/area chart + top-pages & top-referrers tables. Lightweight hand-built SVG charts (no heavy dep) or `recharts` if needed.
- **SEO score:** `src/lib/pagespeed.ts` — server fetch to PageSpeed Insights API (`PAGESPEED_API_KEY`, env) for `NEXT_PUBLIC_SITE_URL`; `revalidate`-cached (e.g. 6h). Widget shows Performance/SEO/Accessibility/Best-Practices gauges. Graceful fallback if key missing.

## Out of scope
Content CRUD. Per-post analytics breakdown (could be future).

## Acceptance tests
1. Browsing public pages inserts `PageView` rows (verify in Studio/DB).
2. `/admin` shows non-zero totals, a chart, and populated top-pages/referrers.
3. Requests with `DNT:1` and known bot UAs are excluded.
4. `/admin` itself is not tracked.
5. SEO widget renders scores (or a clean "add PAGESPEED_API_KEY" fallback).

## Gate (exit)
Tests pass → unlocks **M4**.

## Human steps required
(Optional) Create a Google PageSpeed Insights API key → `PAGESPEED_API_KEY`. Without it the widget shows a fallback; everything else works.
