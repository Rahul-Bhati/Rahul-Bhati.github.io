# PRD — M5: Project CMS + editable links/fields

## Goal
Manage projects from `/admin` (mirroring the blog CMS) and edit all site links (socials, hero pills, YouTube, footer) without touching code.

## Why
Projects need the same DB-backed, SEO-ready treatment as blogs, and Rahul wants to update links/fields himself.

## Scope
- **Project CMS:**
  - `/admin/projects` list + `/admin/projects/new` + `/admin/projects/[id]` edit: title, slug, description, status, gradient (picker), year, overview, problem, techStack (tag input), demoUrl, githubUrl, cover/media, SEO overrides.
  - Actions (`src/app/admin/projects/actions.ts`): create/update/delete, auth-guarded, zod-validated, `revalidatePath('/projects')` + `/projects/[slug]`.
  - Reuse `src/lib/seo.ts`: `buildProjectMetadata(project)` + `projectJsonLd(project)` (`CreativeWork`/`SoftwareApplication`).
- **Public:**
  - `/projects` (`src/app/projects/page.tsx`) — DB-backed list.
  - `/projects/[slug]` — `generateMetadata` + JSON-LD + `generateStaticParams`.
  - Drawer reads DB.
- **Editable links:**
  - `/admin/links` — manage `SiteLink` rows grouped by `LinkGroup` (SOCIAL/PILL/FOOTER): label, href, platform, tone (pills), order (drag or number), visible toggle. Add/edit/delete.
  - Actions: CRUD + `revalidatePath('/')`.
  - Public read: `src/lib/site-links.ts` fetches links; `hero.tsx`, `navbar.tsx`, `footer.tsx` consume DB rows. `src/lib/icon-registry.ts` maps `platform` string → icon component (built on `src/components/icons.tsx`).

## Out of scope
Sitemap/OG/llms.txt/deploy (M6).

## Acceptance tests
1. Create/edit a project → shows on `/projects` and `/projects/<slug>` with correct metadata + JSON-LD.
2. Delete a project → removed from site.
3. Edit a YouTube/social link in `/admin/links` → reflected on the live site (hero/navbar/footer) after revalidation.
4. Toggle a link's `visible` off → it disappears publicly.
5. Reorder links → order respected on the site.

## Gate (exit)
Tests pass → unlocks **M6**.
